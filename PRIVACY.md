# Privacy & data handling

Live Translate is open-source, self-hosted example software, not a hosted product
run by anyone in particular. There is no company operating a public instance of
this app and no central database of users. Whoever runs an instance — on their
laptop, or deployed somewhere reachable by others — is the one processing data
for that instance.

This document describes, precisely, what the code in this repository does with
data as shipped. If you deploy this beyond your own local testing, read the
["If you deploy this"](#if-you-deploy-this) section below — you're responsible
for your own privacy notice to whoever uses your deployment.

## What data exists, and where it goes

| Data | Origin | Where it goes | Persisted? |
|---|---|---|---|
| Display name | Typed into the pre-flight form | Sent to LiveKit as the participant's `name`; visible to everyone else in the room | Browser `sessionStorage` only (`lt.displayName`) — never written to any server-side store |
| Chosen language | Picked in the pre-flight form / in-call language pill | Sent to LiveKit as a participant attribute (`lang`); readable by every other participant and by the translator agent | Browser `sessionStorage` only (`lt.lang`) |
| Microphone audio | Your device's mic, captured only after you explicitly unmute | Streamed via WebRTC through LiveKit to other participants; when a listener needs a different language, also streamed by the Python agent to Google's Gemini Live API for translation | Not written to disk anywhere in this codebase (see [No recording, by construction](#no-recording-by-construction)) |
| Translated audio + captions | Generated by Gemini Live from the speaker's mic audio | Published back into the LiveKit room as an audio track and a `lk.translation` text-stream; rendered client-side in the captions sidebar | Captions live only in React state in the listener's browser tab; gone on refresh or leave |
| Room ID | A `crypto.randomUUID()` generated in the browser when you click "Create session" | Becomes the LiveKit room name; embedded in the shareable URL | Not stored anywhere — it's just the URL path |
| Everything else | — | — | There are no accounts, no login, no cookies, no analytics, and no database anywhere in this stack (see `package.json` / `pyproject.toml` — no DB driver, no analytics SDK is a dependency) |

## No recording, by construction

Nothing in `src/` or `translator/src/` writes audio, video, or transcripts to a
file, a database, or any third-party logging/analytics service. Audio is
transcoded in memory (`translator/src/audio.py`) and forwarded live; it isn't
buffered to disk. LiveKit's own [Egress](https://docs.livekit.io/home/egress/overview/)
recording feature is not configured or used anywhere in this repo. If you (as
an operator) later add Egress, transcript logging, or any analytics SDK to your
deployment, that changes this picture — update your own privacy notice
accordingly.

## Infrastructure-level logs (self-hosted deploy)

The above is about the *application*. If an operator uses this repo's
`compose.yaml` + `Caddyfile` reference deployment (see
[SETUP.md](SETUP.md#all-in-one-with-docker-compose--caddy)), two more sources
of data exist that aren't part of the app's own code:

- **Caddy's access logs.** The `Caddyfile` here has no `log` directive, so
  Caddy doesn't write structured access logs to a file by default — but its
  process output (which includes connection-level info) still goes to
  `docker compose logs caddy`, and Docker's default logging driver persists
  container stdout/stderr to disk on the host (rotated, not shipped anywhere)
  until that container is removed.
- **The `web` and `translator` containers' own logs** (`console.log`/Python
  `logging` output, e.g. the router's `logger.info(...)` calls in
  `translator/src/router.py`) go the same way — to `docker compose logs`,
  retained on the host per Docker's log rotation, not sent to any external
  logging or analytics service by this codebase.

None of this is shipped off the host by anything in this repo. It's readable
only by whoever has shell access to the machine running `docker compose`, and
it's the kind of infrastructure log that's normal for any reverse-proxied web
service — but it does mean the "not persisted" claims elsewhere in this
document are about the *application's* handling of the data in that Data
table, not a guarantee that no request metadata (IP address, timestamp) is
ever written to disk anywhere in a self-hosted deployment.

## Third parties involved

Running a call necessarily sends data to two services you configure with your
own API credentials:

- **LiveKit** (Cloud or self-hosted) — the WebRTC media/data infrastructure
  every participant's audio and attribute updates pass through. See
  [LiveKit's privacy policy](https://livekit.io/privacy-policy) if you use
  LiveKit Cloud. If you self-host LiveKit instead, no data leaves
  infrastructure you control for this part of the pipeline.
- **Google Gemini Live API** — the translator agent (`translator/src/session.py`)
  opens a WebSocket to `generativelanguage.googleapis.com` and streams a
  speaker's raw microphone audio (as 16 kHz PCM) whenever at least one listener
  needs a different language, receiving back translated audio and a text
  transcript. This is governed by
  [Google's Gemini API terms and privacy policy](https://ai.google.dev/gemini-api/terms).
  Audio for a speaker/listener pair sharing the same language is **never** sent
  to Gemini — the router (`translator/src/router.py`) skips those pairs
  entirely, both for cost and so monolingual rooms never touch a third-party AI
  model.
- **Google Fonts** — `src/app/globals.css` loads Inter and JetBrains Mono via
  an `@import` of `fonts.googleapis.com`/`fonts.gstatic.com`. Every visitor's
  browser fetches these files directly from Google, which means Google's font
  CDN sees the visitor's IP address and standard request metadata (user agent,
  referrer) on every page load — independent of anything happening in a call.
  This is a common, low-sensitivity third-party call, but it is a third party
  outside of LiveKit/Gemini, and it fires for the landing page too, before
  anyone joins a room. If you'd rather not send that request to Google at all,
  self-host the fonts (e.g. via `next/font/google`, which bundles the font
  files at build time instead of fetching them client-side) and drop the
  `@import`.

No other third party is contacted by this codebase. There's no ad network, no
crash reporter, no product analytics.

## Access control

Anyone who has the session link can join, up to `MAX_PARTICIPANTS` (8 by
default). There's no password, invite approval, or waiting room built in — the
URL itself is the access control. Treat it accordingly: don't post a session
link somewhere public if the conversation shouldn't be public.

## Data lifetime

- Rooms close automatically when empty: 60 seconds after being created with no
  one in it, or 30 seconds after the last participant leaves (`emptyTimeout` /
  `departureTimeout` in `src/app/api/token/route.ts`).
- Separately, each access token is only valid for 4 hours (`SESSION_TTL_SECONDS`).
  That's a cap on how long a token can be used to *join or reconnect* — it does
  not forcibly end an active call. A room where people stay continuously
  present isn't automatically disconnected at the 4-hour mark.
- Once a room closes, the LiveKit room, the agent's per-pair Gemini sessions,
  and any in-memory caption state are gone. There is nothing left to delete
  because nothing was retained.
- Display name and language choice live only in the joining browser's
  `sessionStorage`, which the browser itself clears at the end of that
  session/tab lifetime.

## If you deploy this

See also [SECURITY.md](SECURITY.md) for how secrets are (and aren't) kept out
of the deployed images — a data-handling document isn't complete without
knowing the credentials involved aren't leaking somewhere unintended.

If you run an instance of this app for anyone other than yourself:

- You are the data controller for that instance under most privacy laws
  (GDPR, CCPA, etc., depending on who's using it and from where).
- Publish your own privacy notice covering: your identity/contact info as
  operator, that microphone audio is processed by Google's Gemini Live API for
  translation, that LiveKit (Cloud or your own server) carries the media, and
  how long you personally retain any logs your deployment adds beyond what's
  described above.
- Get clear consent before granting microphone access — this app requests it
  via the browser's standard mic-permission prompt, but that's not a substitute
  for informed consent about third-party AI processing of voice data.
- This project has no age gating or content moderation. If your deployment is
  reachable by children or the public, you need to add your own safeguards.
- Review [LiveKit's](https://livekit.io/privacy-policy) and
  [Google's](https://ai.google.dev/gemini-api/terms) current data-processing
  terms yourself before relying on the summary above — this document reflects
  this repository's code as of the time it was written, not those providers'
  live legal terms.

## Changes

This file describes the code, not a fixed legal promise. If the code changes
(e.g. someone adds recording, analytics, or a database in a fork or a future
commit), this document should be updated alongside it — it's accurate only to
the extent it matches what's actually running.
